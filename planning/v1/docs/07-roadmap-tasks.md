# 07｜實作順序與可派工任務

## 1. 分段交付，不一次做完所有模組

| 階段 | 完成後能做什麼 | 不在這一階段做 |
|---|---|---|
| M0 開發基礎 | Xcode 可建置、測試可跑、本地持久化已驗證、依賴可重現、技術決策有紀錄。 | 學習算法、漂亮首頁、全量生成、帳號同步。 |
| M1 內容 pilot | 200 詞 + 30 片語有來源、義項優先分級與合理語境選詞題，內容包可重建。 | 一口氣生成全部十萬題、完整考古題統計平台。 |
| M2 離線字典與資料安全 | 查字、一鍵加入、批次匯入、local persistence、可備份還原。 | 學習效率模型的高階訓練。 |
| M3 核心學習循環 | 以語境選詞為主的有效作答 -> 可追溯證據 -> 記憶排程與下一題；避免重複複習義務、可續接。 | 複雜 deadline 最佳化、fatigue personalization。 |
| M4 自動規劃 | 每日時間與原始考試範圍／期限約束、forecast、合理調整新舊內容、資料夠多時的本機記憶校正。 | 精確因果得分率模型、CloudKit、Android、付費。 |
| M5 完整內容與可靠性 | 內容擴展、版本遷移、壞題撤銷、實機負載、可供同學測試。 | 對外宣稱經證明提升學測成績。 |
| M6 beta 與校正 | 跨日使用、修內容/體驗，以相同時間的未見語境題與原始範圍覆蓋檢驗效果。 | 無資料就上大型自適應模型；未通過 privacy gate 不啟用研究上傳。 |

里程碑用驗收 gate，不承諾幾天完成。資料授權、全量內容審查和真實延遲測試可能比寫 UI 更慢。

## 2. 主線依賴

```
M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6
                   \------ 備份/還原 ------/
       內容 pipeline 在 pilot 穩定後可與 App 開發並行
```

內容全量化應等 M3 題型與 scorer 的格式穩定，再大規模執行；不要先生成後全部重做。
一個 milestone 裡可以完成多個小提交，每個 coherent change 執行對應測試，不每改一行就全專案 build。

## 3. 任務清單

任務以 `contracts/tasks.json` 為機器可讀來源。下表是相同內容。

### T001 · M0 · 建立 App 與測試基礎
依賴：無。
驗收：實際 Xcode toolchain 可 build 並在 Simulator 執行空 App；automated test 可跑；記錄 Xcode/Swift/SDK 版本。

### T002 · M0 · 驗證本地持久化與可重現依賴
依賴：T001。
驗收：實際保存並重新讀取簡單測試資料；主要 dependency 版本鎖定可重現；學習算法不在 M0 接入。

### T003 · M0 · 接現有 OpenCode 的 Xcode MCP
依賴：T001。
驗收：保留 OMO/既有設定；列出工具、成功讀專案/build；沒有 MCP 時記錄 CLI fallback。

### T004 · M0 · 記錄 M0 技術決策
依賴：T002, T003。
驗收：持久化佈局、時間/ID 慣例等仍不確定的重要選擇留下簡短 decision note；不為同步、Android、複雜算法預先工程。

### T005 · M1 · 來源登記、授權 gate 與自有 IDs
依賴：T004。
驗收：每個來源有狀態／授權條件；pending 無法進不適用發布包；自有 ID 不依供應商；考題分析素材另走權利 gate。

### T006 · M1 · 50 詞內容流水線試跑
依賴：T005。
驗收：生成／審查可恢復；試行義項／用法三層優先度及合理語境選詞題審查；記錄成本與可發布率，不把 credits 當 API 無限額。

### T007 · M1 · 200 詞 + 30 片語 pilot
依賴：T006。
驗收：有多義、重要第二義、詞形／片語難例及粗分級理由；主力句子留空選字、合理干擾項與 train/check family；全部啟用目標有合格題，歧義隔離。

### T008 · M1 · 內容包建置器
依賴：T007。
驗收：可重現的內容包：搜尋索引、版本 manifest、完整性檢查與授權標示一起產生；所有 cross-reference 有效。

### T009 · M2 · 離線搜尋與字典頁
依賴：T008。
驗收：英文 prefix/alias、詞形、多義與片語顯示；大小寫不敏感；未知字外連。

### T010 · M2 · 明確一鍵加入與批次輸入
依賴：T009。
驗收：去重、撤銷、保留片語、歧義清單；沒有查詢自動加入。

### T011 · M2 · 個人 DB 與原子作答基礎
依賴：T010。
驗收：enrollment/presentation/event/draft 可保存；重複 ID 不重複寫入。

### T012 · M2 · 本地備份/匯出/還原
依賴：T011。
驗收：一致性快照 + 可攜式匯出（格式由實作決定）；空白安裝可恢復；損壞檔不毀原資料。

### T013 · M3 · 客觀評分與字串正規化
依賴：T011。
驗收：大小寫永不扣；有提示無 Good；拼字/回想分離；歧義 unscorable。

### T014 · M3 · FSRS adapter 與參考向量
依賴：T013, T002。
驗收：選定並鎖定 FSRS-6 實作（確認 21 參數與 license）；Again/Good、同日/跨日/失敗一致；正式確認 wrapper learning steps 與曝光例外。

### T015 · M3 · target/能力狀態與 replay
依賴：T014。
驗收：不同義項與 recognition／production 證據可區分、事件重放一致；同題不產生多份獨立 Good、未直接測到的能力不得冒充通過；不強制每個模式獨立複習。

### T016 · M3 · 教學與主要題型 UI
依賴：T013, T015。
驗收：句子留空、從英文選項選詞為主；搭配／多義辨識及輔助解釋題、少量輸入；不把看到英文後猜義等同於選詞能力，沒有自評按鈕。

### T017 · M3 · 下一題策略與續接
依賴：T016。
驗收：避免同題／答案曝光造成虛假成功和重複密集練習；選項順序保存、原子提交、隨時退出可恢復。

### T018 · M3 · 短文小題組與 writing 目標
依賴：T017。
驗收：短文題組取代部分重複單題，共享閱讀時間，完成一部分仍可保存；文章中僅出現但未測的詞不算成功複習；書寫提高指定要求，不扣大小寫。

### T019 · M4 · 有效時間計量與個人成本
依賴：T017。
驗收：排除背景，標長停頓；按題型 shrunk median/P75；原始 slices 可查。

### T020 · M4 · 全域預算與每日分配
依賴：T019。
驗收：到期、考試新內容及檢查共用每日總時間；不強迫清光 backlog，額外學習須使用者自行選擇；漏學不倍增，必要的舊項也不長期餓死。

### T021 · M4 · 考試與 scope 自動調整
依賴：T020。
驗收：以原始考試範圍、期限、每日時間與是否 Writing 為限制，優先提高未見語境答題能力；兼顧覆蓋／重要複習／低價值深度取捨；不縮小原範圍分母、不改鬆評分；考後保留歷史。

### T022 · M4 · 期限 forecast 與情境模擬
依賴：T021。
驗收：重用實際選題與預算規則、估後續複習；快／中／慢短缺及未覆蓋明示；不把未校準 FSRS retention 顯示成考試分數；可取消、離主執行緒。

### T023 · M4 · 查詢診斷與提示節流
依賴：T022。
驗收：14 天內 3 個不同日期等查詢提示規則可配置；未加入仍須點擊；已有曝光不虛增穩定度。

### T024 · M4 · 啟動路由與 widget 搜尋入口
依賴：T020, T009。
驗收：有任務/完成的預設正確，deep link 優先，不另建一份使用者資料存放。

### T032 · M4 · 本機個人化記憶參數校正（資料充足才啟用）
依賴：T015, T017。
驗收：只用本機有效歷史；資料量不足時保持起點，嘗試擬合須以未參與擬合的資料確認預測未變差，避免既有排程突然大幅跳動，失敗可退回；個人參數不離開裝置。實作時決定可行的參數子集與門檻，不因沒有足夠資料阻擋早期學習。

### T025 · M5 · 扩展核心詞與題庫
依賴：T008, T018。
驗收：先核心批次再擴到約 10k–12k 詞加片語；義項／用法粗分級來源與必要題族可審查，語境選詞題避免答案線索漏洞；有完整 provenance 與品質報告，不要求完整考古題機率模型。

### T026 · M5 · 內容升版/壞題撤銷/義項改版
依賴：T025, T015。
驗收：舊ID可追溯；不複製舊掌握到新義；舊事件可排除/replay。

### T027 · M5 · 功能與故障測試整合
依賴：T024, T026, T012, T023, T032。
驗收：06 §2 列出的關鍵 QA 全部通過、其餘 QA 有執行紀錄，包含語境選詞效度、證據去重、固定時間與考試原始範圍；kill／交易／跨日／多考試／壞題／restore 有實測。

### T028 · M5 · 實機效能與無障礙
依賴：T027。
驗收：真實內容 + 100k events 場景量測；VoiceOver/大字/離線音訊有結果。

### T029 · M6 · 同學 beta 安裝與說明
依賴：T028。
驗收：合法簽名/渠道、離線限制、備份、資料刪除、已知問題；不擅自付款。

### T030 · M6 · 跨日 beta 與內容修正
依賴：T029, T033。
驗收：同學自願使用及跨日測試；以本機與合法取得的群體摘要評估延遲未見語境題、時間成本、原始考試範圍覆蓋；不匯出個人原始學習史，未通過 T033 的 privacy gate（beta 為單一聚合方過渡版）不啟用遠端研究貢獻。

### T031 · M6 · 基線評估與後續優先序
依賴：T030。
驗收：報相同投入下的未見語境題結果、考前範圍覆蓋、時間誤差、負荷與侷限；評估是否真有益，決定下一批實驗，不能將模擬加成當真人實證。

### T033 · M6 · 自願群體研究聚合（獨立隱私驗收）
依賴：T028。
驗收：任何遠端研究 contribution 必須 explicit opt-in，使用者拒絕仍完整可用；符合 docs/privacy-data-collection.md 方案 A 的來源分離、最低群體門檻與日誌／重識別限制。beta 可用單一聚合方過渡做法（保證較弱、同意畫面明確告知、單一 contribution 不落地、不記 IP）；正式公開前改為多方安全聚合，做不到就不啟用。研究功能不阻擋離線核心 App。

## 4. OpenCode + OMO 的工作分配

一次指定一個 milestone，主 agent 負責整合：
- app/domain agent：App 與學習核心邏輯，不能改內容 schema 而不通知整合者。
- content agent：pipeline/fixtures/provenance，不改個人學習狀態定義。
- tests/review agent：獨立驗收，先看資料完整性和錯誤評分，不只看格式。

schema/migration、Package.resolved、Xcode project 設定一次只有一個寫入者。
子 agent 可先提出差異或在不同分支工作，不讓多個進程同時修改同一個 Simulator/local DB 或打架寫 pbxproj。
不用為了這個專案增加一堆新 harness/插件；保留使用者既有 OMO。

每個任務交付必須包含：
變更檔案、通過/未跑的測試、資料/政策版本、已知限制、下一個可執行任務。
不把「看起來可編譯」寫成「build 成功」。

## 5. 後續階段，先不實作

P1 Apple 裝置同步：真的有多 Apple 裝置需求後再做 CKSyncEngine adapter、account lifecycle、衝突與離線合併演練。[S12]
P2 Android/桌面：依實際測試群決定 client 技術與中立 backend；共用內容 ID、事件 contract、政策 test vectors。不可讓两个獨立雲都掌管同一份狀態而沒有合併規則。
P3 進階個人化：V1 的本機 FSRS 校正見 T032；後續再根據足夠延遲資料評估 logistic calibration、跨題型遷移與效率下降模型。
P4 收費/開源：分離 code/content 授權；不把營運決策塞入 V1 核心架構。
