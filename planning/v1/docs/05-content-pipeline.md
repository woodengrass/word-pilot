# 05｜詞庫與題庫：內容目標、來源與品質

## 內容目標

V1 正式內容約 10k–12k 英文 headword，另有獨立常用片語集合。

數量不是主要品質指標。每個可學項目需要足夠的：

- 詞性與重要義項。
- 自然繁中解釋。
- 例句。
- 搭配／用法。
- 詞形／別名。
- 可用於學習與檢查的題目。
- provenance。

先用小型 pilot 驗證內容格式與學習系統，再擴大，不必預先規定 pilot 一定經過幾個 pipeline stage。

## 資料來源方向

### CEEC

大考中心高中英文參考詞彙表很適合作為台灣高中 coverage / priority 參考。[S01][S02]

但它不是完整雙語詞典，也有實際使用／再散布條件。是否可用於公開、營利或開源內容包，需要依實際授權確認；不能因為 beta 免費就推論所有未來用途都沒問題。

### Open English WordNet

可作 sense、part-of-speech、semantic relation 的參考候選。[S16][S17]

它的 sense granularity 不一定適合高中學習，因此只作來源，不要求 UI 原封不動呈現。

### 其他頻率資料

wordfreq 等可以作候選排序，但要分清楚程式碼授權與資料授權。[S18]

### 自建內容

繁中解釋、例句、搭配與題目可以由專案自行撰寫，或用 LLM 大量生成／審查。

AI credits 可以積極使用在 build-time；App runtime 不需要 LLM。

## Provenance 是硬需求

至少要能回答：

- 這個欄位／題目從哪裡來？
- 用了哪個版本的來源？
- 來源授權是什麼？
- 是直接取用、改寫、人工撰寫還是 AI 生成？
- 如果由 AI 生成／審查，用了哪個模型／prompt 版本？
- 後來是否被人工修正？
- 如果來源需要換掉，哪些內容受影響？

具體用 SQL、JSON、metadata tables 還是其他表示，由 content tooling 實作時決定。

## AI 可以做什麼

適合：

- 將來源 sense 整理成適合學生的義項候選。
- 生成繁中解釋、例句、搭配與題目候選。
- 第二模型／不同 prompt 交叉審查。
- 隱藏標準答案後重新解題，找出多解。
- 標記過難詞彙、語法問題、可疑搭配與重複 sense。
- 對 10k+ 詞做大規模一致性 review。

AI 不應被當成：

- 授權判斷器。
- 100% 正確的唯一審稿者。
- 可以把受限來源「改寫一下就變乾淨」的工具。

LLM judge 有已知偏差，因此需要程式檢查、來源核對與人工高風險抽查。[S19]

## 題目品質目標

每個真正用來估計 mastery 的題目必須盡量做到：

- 有明確 primary target。
- 答案唯一，或列出所有可接受答案。
- 不靠選項長度、詞性明顯不符等方式洩漏答案。
- 題幹語境真的使用目標義項。
- 不把同一句只換人名當成新的 transfer evidence。
- learning/training 題與用來驗證 transfer 的題目有所區隔。
- 有疑義時寧可 quarantine，不要把內容錯誤算成學生不會。

具體一個 target 要幾道題、怎麼分 train/check，應先由 pilot 的實際重用率和學習驗證決定，不在規劃階段固定數字。

## 內容版本

內容更新不能讓學習歷史失效。

- 只改文字表述，可保留 identity。
- sense 的實際語義被拆分／合併時，要明確做 mapping 或要求重新驗證。
- 壞題撤銷後，相關 evidence 應能被排除或重新計算。
- 換詞庫供應商不應直接等於「所有使用者重新開始」。

## 內容完成條件

一個正式內容包至少要：

- 來源與權利狀態可追溯。
- 搜尋／別名不產生未處理的重大碰撞。
- 核心義項與用法可讀、自然、符合目標程度。
- 真正啟用的 learning target 有足夠合格題目。
- 有自動檢查、AI review 與人工抽樣紀錄。
- 能產生版本與變更報告。

內容工具的具體流程、檔案格式與並行方式由 agent 根據實際規模設計。
