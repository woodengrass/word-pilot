# 05｜詞庫、題庫與來源建置

## 1. 資料不是附帶工作

完整詞庫目標為約 10,000–12,000 個英文 headword，加一個初始常用片語集合。計數不把英美拼法、屈折形式與同字多義灌成不同單字。
約 6,000 詞的大考中心現行參考表是高中覆蓋基準；「7000 單」不是目前這份官方表的精確詞數。[S01]
資料完成度與 App 功能完成度分開追蹤，不能用「已匯入一萬個英文拼字」代替完整詞庫。

第一個可跑通的內容集：200 詞 + 30 片語。選入：
高頻普通詞、多義詞、不同詞性、相似拼字、英美變體、可分離片語、介系詞搭配、常見屈折歧義。
這是架構與品質驗證集，不是把 V1 的完整內容要求降成 200 詞。

## 2. 來源選擇與授權邊界

| 來源 | 用途 | 發布處理 |
|---|---|---|
| CEEC 詞彙表 | 高中詞彙覆蓋、分級候選 | 封面有非營利使用條件；是否可離線重製、分發級別資料與未來收費，需依實際用途確認。沒有授權確認不默認可商用。[S01] |
| Open English WordNet | 可追溯的義項、詞性與語義參考 | 按所取版本 LICENSE 保留 CC BY 4.0 與底層 Princeton 相關聲明；不要只抄一行授權名稱。[S16][S17] |
| wordfreq（可選） | 英文頻率候選排序 | 程式 Apache 2.0、資料另有 CC BY-SA；隔離為可停用來源，記錄實際所用資料與衍生範圍。[S18] |
| 本專案撰寫/生成後審訂 | 繁中解釋、教學例句、搭配與題目 | 記錄生成輸入與來源；查所用模型服務條款。由受限材料改寫不能自動變成乾淨原創。 |
| Cambridge | 未收錄字的外部查詢入口 | 僅使用者點擊後導向網站，不抓取、打包或重發布。 |

預設不引入来源鏈不清的整合雙語大詞庫。repo 掛 MIT 不等於其中每筆原始辭典文字都確定具備相同授權。
是否開源、是否只給同學、不收費或未來只求回本，都不取代授權核對。

來源採四態：approved / approved_with_conditions / pending / excluded。
發布設定另分 private_development、noncommercial_beta、public_distribution；它們是檢查設定，不是法律豁免。
pending 或條件未滿足的資料不得進對應的可發布包。
CEEC 許可尚未確定時，工程可用自建 pilot 包繼續，不必停工，也不對外宣稱官方授權或完整官方級別支援。

## 3. 自有穩定 ID 與 provenance

本專案自己的 entry_id / sense_id / target_id 不能等同某供應商 ID。來源 ID 放 mapping；換辭典供應商不改使用者歷史的身份。

每個可追溯欄位至少有：
- artifact_id、entity_id、field_path、內容 hash、artifact_version。
- source_id、source_record_id、取得日期、原始資料版本/hash。
- license_id、授權文字/條件快照參照、發布允許狀態。
- derivation：direct / adapted / generated / editorial；輸入 artifact 的 IDs。
- generator：provider、實際 model identifier、prompt_hash、schema_version、generation_time。
- review：reviewer/model、盲審或帶來源核對、判決、錯誤標籤、review_version。
- 人工修改理由與替代舊版本的關係。

多來源共同產生同一欄位時保留多條 dependency edge，不能以單一 source 字串覆蓋。
App 只需帶可顯示的授權/來源摘要；完整 prompt、原始來源快照及審查產物留在開發內容倉，不把機密 API key 或個人訊息包進 App。
先用 SQL 表 + JSON payload，不做複雜圖資料庫。

## 4. 可恢復、可重跑的內容流水線

```
原始來源登記及授權 gate
  -> 目標 headword / phrase 清單
  -> 自有 ID 配對、屈折與變體正規化
  -> 義項篩選與學生用法結構
  -> 生成繁中解釋 / 搭配 / 例句候選
  -> 內容核對
  -> 出題候選（train / check 分開）
  -> 隱藏答案的獨立解題 + 干擾項審查
  -> 程式驗證與人工風險抽查
  -> 可发布內容與 quarantine 分流
  -> 建置 SQLite、FTS、manifest、attribution
```

每一階段輸出具 hash 的 JSONL。相同來源版本 + prompt + schema + model configuration 可命中快取；失敗可局部重跑，不重生成所有 ID。
模型 provider 是可替換 runner；也接受外部工具產出的 JSON 檔，避免被 API 計費或登入方式鎖死。
使用者的 credits 不一定等同所有模型 API 配額。先用 50 詞量測實際可用調用方式、tokens、錯誤率與修訂輪數，再排全量作業；不假設聊天訂閱可以無限 API 呼叫。

## 5. 生成與審查的職責

生成器：
- 針對台灣高中程度，用繁中，避免逐字機翻。
- 每義包含清楚解釋與至少一個對應語境；搭配掛到實際義項或用法。
- 不為了湊數生成牽強的搭配或過細義項。
- 「考試重要」分級標成 editorial judgment；除非有可合法使用的實際題目/語料統計，不能說是實測出題頻率。
- 詞族只建立關聯，不預設全部加入學習。
- 片語保留字序、必要介系詞、槽位、可分離/不可分離、合法形式。

內容審查器：
- 檢查義項與中英對應、詞性、自然度、語法、台灣用語。
- 例句必須支持指定義，而不是只出現相同拼字。
- 找出省略的重要常見義、錯誤合併、重複與過度專業內容。
- 翻譯、搭配、句子難度與題目有效性分開判決。

題目盲審器：
- 看題幹、選項與需要的上下文，不看標準答案。
- 提出所有可接受選項及理由，不只是選一個「最像標準答案」。
- 第二次帶來源與答案核對；不同模型/提示的分歧進 quarantine。
- 故意替換選項順序測試位置偏誤，抽查語法是否洩漏答案、句外常識是否代替詞義。
- 已出現在字典頁的例句不能成為「未見語境」check 題。

LLM 全量檢查值得做，但多個模型可能共享錯誤。LLM judge 已有位置偏好、自偏好等已知限制；交叉同意不等於正確證明。[S19]
因此要保留來源核對、程式檢查與人工抽樣，尤其錯誤義項與多答案題。

## 6. 每個目標的內容包規格

第一版最低：
- 每個可發布義項：一條繁中解釋、一個受控例句；適合時提供核心用法，不機械強迫所有詞都有多個搭配。
- 每個啟用的核心 target：至少 3 個有效 train family、2 個獨立 check family，才能宣稱有跨情境的測量能力。
- 資料不足的目標可在字典查，但標記「學習內容尚未備妥」，不啟用無法評分的題目排程。
- 已完整加入 V1 學習範圍的詞，核心義和主要用法必須具備可學內容；不能讓大多數字停在字典-only。
- check 題庫有限，使用過後只能當已見題。沒有未見題就顯示證據不足，不複用舊題冒充遷移測驗。
- 語境 family 不是句子字面 hash：只換人名、地點或選項次序仍屬同 family。

題庫規模按 target 算，不按 headword 算：
12,000 詞 × 每詞數個 target × 多個獨立題型，可能很快超過十萬題。
因此先跑 pilot，量測可發布率與每個可發布題目的成本，再批量擴展。不要把「一萬條翻譯」誤當這個產品的全部內容量。

## 7. 發布 gate

自動硬門檻：
- JSON/SQL schema、唯一 ID、外鍵/跨庫引用、合法 enum、所有權利依賴通過。
- 所有 published 題有唯一明確答案或完整可接受集合；重複選項、空字串、答案外露、目標不匹配皆阻擋。
- 所有詞形與搜尋別名的碰撞有明確處理，不默默覆蓋。
- FTS 可重建；manifest hash、內容量、最小 App 版本與授權清單一致。
- generated_raw / disputed / rejected 不進正式題庫。
- 升版不得重用已改語義的 sense_id；已作答題目不原地改答案。

人工樣本：
每批分層抽樣，覆蓋多義、抽象詞、罕見義、片語、易混字、不同生成批次與審查分歧。pilot 至少人工檢查 100 個隨機題 + 全部高風險/分歧題；此數字是起始工程門檻，不是錯誤率保證。
若樣本發現嚴重錯誤，阻擋對應批次並擴大審查，不能只修抽中的那一題。
每次報告：生成数、通過数、隔離数、人工樣本、錯誤類型與覆蓋缺口。

## 8. 打包與更新

V1 詞庫和 App 一起更新；沒有背景下載器。
下載/遠端增量包、簽章驗證與付費內容交給以後；目前仍做 hash 完整性與版本相容。
使用者回報寫入本機；提供可主動分享的問題檔供測試，純離線版不假裝已送到伺服器。
更换高品質授權來源時，用新來源映射到自有 ID、跑義項差異審查、必要時要求新證據；不是整包換掉仍宣稱進度完全不受影響。
