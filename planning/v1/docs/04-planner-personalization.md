# 04｜時間預算、考試規劃與個人化

## 1. 系統要最佳化的事情

**有考試期限時：**以學生指定的字詞範圍、截止日期、題型／是否需要書寫及每日可用時間為限制，盡量提高考試當天對**未見、具代表性的語境題**的預期表現。**沒有期限時：**在同樣有限時間內持續提升長期有用的詞彙能力，不追求所有義項一律維持最高 retention。

這是產品目的，不代表 V1 已能精準估算每分鐘可增加多少分數。FSRS retention、已開始字數、foundation_verified 與 backlog 都是用來規劃／驗證的代理量，不得取代學生成效；避免為了達成代理指標而製造無止境的複習工作。

V1 是可解釋的受限制規劃器，不宣稱已找到每分鐘真正的因果學習收益或全域最適解。相關最佳化研究是在特定記憶/成本假設下成立，不能直接背書本產品的 heuristic。[S26]

輸入：
每日時間 B、已用時間、所有 active enrollment、考試日期與目標、target 狀態、候選題及耗時估計。

輸出：
今日下一個 action、今日新內容准入、逐考試可行性範圍、未排入原因。每個決策保存 policy_version 與 reason_code。

## 2. 兩個不同的規劃尺度

### DailyPlanner

做當天的工作量與目標深度選擇，輸出時間額度和 eligible target。
首次開啟、日切換、大批匯入、考試改期/移除、時間预算變更時重算。
少量作答只增量更新，不每題重跑整個月。

### NextActionPolicy

在當天額度內選下一道題/教學；應快速回傳，不做網路呼叫。
已呈現的題目 pin 住；不因背景重新計畫換掉使用者正在讀的內容。
它執行 DailyPlanner 的限制，而不是另一套互相搶控制權的 scheduler。

## 3. 計時

使用 monotonic clock 計算單次停留；UTC 時間記錄事件時間；本地日期只用於日預算。牆上時間修改不能產生負的作答秒數。

只計學習畫面上的活動時間；字典任意查閱不吃每日學習額度。學習題幹、輸入、回饋、短教學的時間都要計，不可只算按答案那幾秒。

退到背景/鎖定立即暫停；同一題回來接續。長時間無操作可能是離席也可能是閱讀，所以保留 foreground_time、idle/censored 標記，不能拿來判斷疲勞或答錯。

工程初值：單段 120 秒以上無活動的尾端列為 uncertain_time，不納入耗時模型；每日顯示為「約」多少分鐘。學習計時可在設定調整，不用跳「你還在嗎」。對長文/無障礙閱讀使用不同的閾值，且不拿 outlier 斷定能力差。

短文多小題共用閱讀片段；同一段閱讀不得對每一題重複計時。未完成題目的有效閱讀時間仍記入當日，但不生成答錯。

跨日時間片切開。預設學習日以本地 04:00 切換，考試時間另用其儲存時區；切換規則存版本，不能回頭改寫已發生日統計。

## 4. 個人耗時模型：V1 就實作

按「單字/片語 × 初次教學/複習 × 題型 × 成功/失敗」分桶，並保留題幹長度和書寫模式。

初期使用保守工程先驗，顯示寬範圍：
- 短教學 15 秒。
- 單句選擇題 12 秒。
- 搭配/片語槽位 10 秒。
- 短輸入 20 秒。
- 一般回饋 5 秒。
- 短文共享閱讀 45 秒，另加每小題成本。

以上全部是估算種子，不是研究測得的全體學生數據。先用內部 200 詞試用的實測替換，再對每人更新。

穩健估計：
`cost = shrinkage * personal_median + (1 - shrinkage) * prior`
`shrinkage = n / (n + 30)`

n 只計有效、未中斷的 observation。規劃用個人/先驗混合的 P75，呈現用中位與較慢情境範圍。失敗造成額外教學/重試應另外計入，不能把「答得快但一直錯」判為高效率。

V1 不必實作複雜線上 quantile 演算法：每桶保留最多最近 200 個合格樣本，算 median/P75 即可。這個小型估計器可直接單元測試。

## 5. 目標深度與降級規則

這裡的 Foundation / Standard / Extended 是內容安排層級，不是所有字都要完成相同次數、相同 retention 的硬性技能清單。具體義項／用法依來源支持的**基礎優先／常用補充／延後學習**分級，以及該場考試的範圍與題型調整：
- Foundation：這次目標真正不可缺的高價值義項及基本語境選詞／搭配能力；可能包含字典第二義。
- Standard：有明顯額外價值的其他義項、常用搭配及跨情境檢查。
- Extended：較低優先度的義項、用法及更全面的語言能力。
- Writing：考試需要書寫時額外提高回想與拼寫要求，不對所有考試強制。

預設對應：內容分級的「基礎優先／常用補充／延後學習」（內容資料草稿中的 core／important／extended）分別對應 Foundation／Standard／Extended，再依該場考試範圍、題型與是否 Writing 調整。

考試快到了時，先暫缓 Extended，再收窄 Standard；不能把 Foundation 縮成只有「看過中文」，也不能全部丟掉搭配/第二義，因為這些本身可能是重要考點。[S02]

單次作答與歷史證據的評分規則不變；**考前「對此題型已足夠」不等於全部義項永久精熟**。已在代表性語境中有充分跨日／跨情境成功證據的能力可以降低密集單題維持成本；仍要在需要時以新題檢查。深度下降只改先學與先練哪些 target，不把失敗改成成功，也不以較小分母偽造 100% 進度。

沒有考試：按一般使用頻率、已加入順序、個人薄弱處與長期價值，漸進加入其他重要義項；不一口氣開全義項，也不因為沒有 deadline 就對低價值義項維持無條件的高頻複習。

## 5a. 動態目標記憶率（手段，不是目標）

目標是在每日時間內，讓考試當天（無期限時則為長期）未見語境題的預期表現最大。目標記憶率只是達成它的旋鈕，由演算法為每個 target 決定，使用者不需設定。考量：

- 內容價值：義項／用法分級，以及是否屬於進行中考試的原始範圍。
- 期限：考前範圍內的 target 以「考試當天的預測記憶」為準，而不只看一般到期日。
- 時間壓力：預測負荷相對每日預算。
- 個人記憶曲線與每題耗時：同樣提高記憶，不同學生的成本不同。
- 已有證據：已有足夠跨日、跨語境成功證據的能力，用較低成本維持。

V1 可實作的做法（工程初值，見 `policy-v1.json` 的 `memory.retention_*`；beta 校正）：

1. 每個 target 的目標記憶率限制在 `retention_bounds`（初值 0.70–0.95）內，不是全體一律 0.90。
2. DailyPlanner 重用 §7 的 forecast，對少數候選設定（例如各價值層的目標記憶率組合）估算目標函數，選每日預算內分數最高的一組：
   - 有考試：考試當天、原始範圍內代表性語境題的價值加權預期答對；尚未接觸的項目以不會計。
   - 無考試：`long_horizon_days`（初值 90 天）內價值加權的預期記憶量。
3. 每 `retention_reselect_days`（初值 7 天）或考試、預算、範圍變動時重選；每次變動不超過 `retention_max_change_per_reselect`，並記錄 reason_code，避免排程忽高忽低。
4. 考前：範圍內 target 若預測在考試當天低於其目標，安排一次考前檢查；考後移除期限加權，回到長期設定。
5. 證據足夠：target 達 foundation_verified，且最近一次跨日檢查成功時，可降到該層較低的維持目標；之後失敗或預測低於目標時恢復加強。
6. 個人資料不足時，從 `initial_desired_retention`（0.90）開始，再依上述規則調整。

這是可解釋的啟發式，不宣稱已找到每分鐘最大得分。是否真比固定 0.90 好，以 beta 相同投入時間下的未見題表現驗證。

## 6. 新內容准入：看未來成本，不只今天

一個新 target 的成本包括：
初次教學 + 短期提取 + 預期錯誤補救 + 規劃期間的後續複習。

某 target 有過往 knowledge evidence，可降低剩餘成本；單純查過不等於免費學會。
加入 2,000 個 word 不代表立即建立所有 sense / response mode 的到期任務，否則第一天就製造不合理積欠。**同一次題目若已直接驗證所需能力，就不能只因另一個邏輯狀態未被「打卡」而立刻重測相同內容。**題組共用閱讀成本，重疊能力只計一次實際呈現，不虛構多次獨立複習成功。

DailyPlanner 為新 target 建候選 packet，每個 packet 有當日成本及未來天數的 cost footprint。
先用當前 FSRS 與工程成本先驗模擬，再用實際紀錄修正。先估與驗證，不宣稱能精確預知每個人的遺忘。

## 7. Forecast 的可實作基線

V1 至少做快／中／慢三個情境，而不是一個「你只要 17.3 分鐘」。預估應以**使用者原始指定的全部考試範圍**為分母，呈現截止前的可能覆蓋及尚缺的部分；尚未校準的記憶預測不能直接標示成「考試能拿幾分」。
- horizon：至少未來 14 日；若有考試，涵蓋最迫近考試，最多展開 90 日。
- 90 日以外只給粗估，不給精準達成日。
- 成本使用個人化 median/P75 與先驗不確定區間。
- 已建立記憶 target 使用 FSRS 的預測作答機率作模型輸入，但標為未校準。
- 新 target 的成功率冷啟動種子由內部測試取得；沒有時保守給範圍，不把種子叫 population parameter。
- 使用固定 seed 的少量（例如 32 條）模擬軌跡，逐日執行相同 NextActionPolicy、記錄成功/失敗與下一次 due。
- first-pass 新內容准入可用各 packet 的獨立 cost footprint 快速估算；最後對整份計畫重跑，因為積欠會互相影響。
- 若慢情境超支，依重要度刪除/延後低優先新 packet，再重算。
- 在背景運算，限制候選數、可取消、保存計畫版本；使用者作答不等待 simulation。

這是估計工具。P10/P90 等百分位在模型未校準前只是「模型情境範圍」，不能叫有 90% 保證的真實信賴區間。

## 8. 下一題選擇與防止負荷膨脹

先排除：未加入、使用者已暫停、無合格題目、答案剛曝光不適合獨立測量、與正在呈現的題目衝突或當下時間不足以開始新題組的內容。正在合法進行的題目可續接，不因背景重算而切走。

在剩下的候選中，以**考試期限與原始範圍、內容重要性、當前有效證據／失分風險、未來複習成本、每日剩餘時間**共同決定：要教新字、加強舊字、檢查弱項或暫停擴充。沒有 deadline 時仍比較長期有用性與成本。V1 用可解釋的啟發式，不宣稱已算出每個 target 的精確「每分鐘增加幾分」。

V1 的具體順序（工程初值，見 `policy-v1.json` 的 `planner`；同樣輸入必須得到同樣結果）：

1. 續接正在進行的合法題目。
2. 今天已開始的短期補救（同 target 同日最多 3 次）。
3. 關鍵維持：Foundation 層或進行中考試範圍內的到期 target，預測記憶低於其目標超過 `high_risk_margin_below_target`（初值 0.10）。
4. 考試覆蓋配額：有考試且原始範圍仍有未接觸內容時，依「剩餘未接觸量 ÷ 剩餘學習日」保留當日新內容配額；此時第 3 項最多使用 `maintenance_share_cap_with_uncovered_scope`（初值 70%）的當日預算。
5. 其他到期 target，依價值加權的風險排序。
6. 一般新內容（無考試，或考試範圍已全部接觸）：新 unit 只有在未來 `admission_horizon_days`（14 天）每日預估複習不超過預算的 `admission_max_projected_review_share`（85%）時才開。
7. 查字後的 pending diagnostic 與跨情境檢查，佔當日預算上限 `diagnostic_share_cap`（初值 10%），不擠掉正常學習。
8. 有餘量再擴展義項／用法。

同一層的排序鍵固定：`deadline_bucket → value_tier → risk_gap（預測記憶低於目標的幅度）→ waiting_age → expected_cost → stable_id`。每個選擇記錄 reason_code。比例與門檻是工程初值，不是最佳值。

必須避免：
- 固定先清光全部到期複習，令期限內仍有大批指定內容完全沒接觸；也不能固定先學新字而長期犧牲必要維持。
- 因為每個義項／題型都有獨立狀態，就機械地要求做完所有重複複習。
- 對已有足夠跨日及跨語境成功證據的能力仍維持昂貴的密集訓練；可降低優先度，必要時再檢查，但不能永久宣稱不會忘。
- 每天自動膨脹到超出預算、以欠題清單逼學生補時，或只為提高表面正確率而出容易題。
- 同題反覆刷到好看；短期補救上限初值是同 target 同日最多 3 次，之後重新教學並留待往後確認。

每個決策應能解釋選題、延後或降低密集程度的原因。當前時間不足、沒有合格題目或計畫目標已達合理程度時，可結束今日安排，不為填滿分鐘數硬湊題。

## 9. 複數考試與公平性

每日時間只算一次；兩場考試共用 target 的作答也只算一次。
每個 target 的必要準備時間取所有相關考試中迫近需求，但可先達近考 Foundation、稍後補遠考 Standard。

同日兩场不同考試互相競爭且確定超時時，按迫近程度與預估達標缺口分配，明示兩場各自未覆盖範圍。不能對每場分別模擬都說可達成。

一般學習與較晚考試可能暫時讓位，但保留等候天數增加優先級；沒有足够時間時仍需誠實顯示延期，不偷偷刪除任务。

## 10. 來不及、漏學、超額

兩千陌生詞一週、每天十分鐘：以模型估算显示明顯不足，不直接除 7 宣稱每天 286 字即可。
優先省下低價值深度與重複檢查，盡量覆蓋**原本指定的範圍**，再補高風險的重要能力。若時間仍不足，明確告知哪些尚未接觸／未充分驗證，而不是縮小分母後宣稱達標；可提示增加時間或調整期限，但不強迫使用者額外設定。

漏學一天：剩餘日子重新規劃，不把昨天全部額外疊到今天造成兩倍任務。
預算滿：停在自然邊界；沒做的內容保留歷史與風險資訊，但下一日**重新排優先順序**，不是把每張舊到期卡永久列為必須清償的債務。「今日完成」不等於全庫到期完成。

使用者自願超額：記錄 override，與平常預算分開；不能把一次超額當他以後每天都有這些時間。

## 11. 長期效率與邊際效益

V1 做得到：個人耗時、錯誤補救成本、延遲語境成功證據、積欠風險及新 target 准入。驗收應比較**相同時間下未見考試型題目表現、考前原始範圍覆蓋、長期負荷趨勢**，不能只把複習任務變少就宣稱學習更有效。

不直接從「越晚題目越錯」推論疲勞；可能是後段題目更難、環境中斷、選題策略或時段不同。學校測驗疲勞研究不是本 App 每日新字上限的直接證據。[S25]

後續研究模型：
用題型、長度、target 熟悉度、lag、是否提示、連續學習時長、當日累計時長預測「延遲後未見題表現」。比較是否加入時長特徵能在 held-out 資料改善預測；先跑 shadow mode，不直接干預。

樣本不足不輸出「你最佳學習上限是 37 分鐘」。一般自適應只降低新內容准入與建議分段，不鎖住使用者，也不顯示醫療/心理疲勞診斷。

模型升級經實驗確認後，才優先用個人化的延遲收益而非固定比例。不得因「疲勞」自動改成大量無效簡單題。
